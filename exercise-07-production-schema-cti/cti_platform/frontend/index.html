Activity for 7.1: Try It Yourself

            Redesign: Deciding Which Source is an Actual Threat
          

          
        


        

          We redesigned the referencing relationship between Sources and Threats into an Embedded Schema (in sources_embedded_threats collection).
          Instead of performing an expensive $lookup join across collections, threats and verdicts are embedded directly inside each intelligence feed document.
        


        
        

          

            

              REFERENCED DESIGN
              
$lookup Join Query

            

            

              -- ms
              Multi-collection Pipeline Join
            

            
db.sources.aggregate([
  { $lookup: {
      from: "threat_reports",
      localField: "source_id",
      foreignField: "source_id",
      as: "reports"
  }},
  { $project: {
      name: 1,
      actual_threats: { $filter: { ... } }
  }}
])

          


          

            

              EMBEDDED REDESIGN
              
Single Document Seek

            

            

              -- ms
              Faster Execution
            

            
db.sources_embedded_threats.find(
  { is_actual_threat_source: true },
  { name: 1, threat_summary: 1 }
)

          

        


        
        

          

            
🚀 What Queries Become Faster?

            
    
              
  • Source Threat Classification: Determining if a source represents an active adversary is instant (O(1) single-document seek).
    • 
              
  • Zero Joins: Eliminates CPU-heavy $lookup pipeline executions across millions of records.
    • 
              
  • Atomic Feed Dossier: Retrieving an intelligence source alongside its top telemetry indicators happens in a single disk read.
    • 
            

          


          

            
⚠️ What Queries / Operations Become Harder?

            
    
              
  • 16 MB Unbounded Growth: If an active feed ingests 50,000+ alerts, the embedded source document will quickly hit the 16 MB BSON ceiling.
    • 
              
  • Write Locking & Contention: Parallel ingestion crawlers concurrently modifying the same source document encounter document-level lock queues.
    • 
              
  • Cross-Source Correlation: Querying if a specific IP hash appears across multiple sources requires complex $unwind pipelines.
    •
